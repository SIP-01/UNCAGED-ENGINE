# Security Audit — SIP-01/UNCAGED-ENGINE — 2026-10-20

## Summary
React/Vite search-engine frontend (TypeScript) with a seed-import CLI (`scripts/seed-import.ts`). Light pass: no server surface, no committed secrets. The seed importer takes the indexer `nsec` as a CLI argument (`--nsec nsec1…`) and never stores or logs it — acceptable, though argv is visible in process lists/shell history. Findings: 0 CRITICAL / 0 HIGH / 0 MEDIUM / 2 LOW.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| UE-L1 | LOW | scripts/seed-import.ts | `--nsec` passed via command-line argument lands in shell history and `ps` output on multi-user machines. | Prefer env var or interactive prompt; document history risk. |
| UE-L2 | LOW | repo root | No SECURITY.md. BYOK provider keys are stored in browser localStorage by design (documented in sip-01-core docs) — XSS in any dependency would expose them. | Add SECURITY.md; consider sessionStorage or warning text in the BYOK UI. |

## Secrets Check
Scanned: package.json, scripts/seed-import.ts, org-wide `nsec1` code search. No committed secrets; seed script decodes operator-supplied nsec at runtime only.

## Dependency Notes
Current mainstream deps (react 19, vite 8, nostr-tools 2.23, zod 4, nostrify 0.52). package-lock.json present. `npm i --silent` inside `build`/`test` scripts mutates deps at build time — unusual; prefer `npm ci` in CI for reproducibility (LOW, not counted).

## Fork/Upstream Freshness
Not a fork.
